## 0. 结论速览（30 秒版）

**Sig 和 DoraHub 不是竞品，是同一块底座（pi-durable）上的两种产品形态：**

| | Sig | DoraHub |
|---|---|---|
| 心智 | **管家**：你说一句话，它调度你各台机器上的 agent 干活，干完汇报 | **驾驶舱**：你亲自驾驶，现场感实时同步（流式/steer/确认卡） |
| 设计中心 | **用户不在场**（quiet by default、推送、卡片决策、预算） | **用户在场**（流式输出、随时插话、远程放行） |
| 会话概念 | 一条与管家的连续对话；「事项 Thread」是对话背后的组织层 | 一个会话 = 一台执行机上的一个 agent 现场 |
| 状态模型 | 三态派生：running / waiting_you / idle + unread，系统推导 | 会话有 status，但列表不按"等用户"组织 |
| 手机 | 一等公民（Chat/Threads/Machines 三 tab 等价功能） | 二等公民（驾驶舱无管理功能，自省 #4） |
| 文档 | spec.md（375 行 PRD）+ 12 篇 ADR + CONTEXT.md 词汇表 + 路由评测集 | PRODUCT.md + roadmap + handoff，**缺功能需求层**（自省 #5） |

**最值得抄的五个点**（详细论证见 §4）：
1. **三态派生状态 + 列表按状态分组 + unread**——用户回来第一眼的信息层级
2. **Needs you 聚合**——所有等用户决策的事（确认卡/未答问题）一个入口，不用逐会话翻
3. **手机三 tab 等价化**——直接回答自省 #4
4. **收尾汇报卡（三段式 + tone 徽章）**——流式戛然而止 → "✅ 完成：改了 2 个文件，测试通过"
5. **恢复/导入链路的语义分层 + 场景测试**——我们四连 bug 的根因答案（自省 #3）

**最不该抄的**：管家 LLM 调度层、记忆模块（容量驱逐/两阶段写入）、Cloudflare DO 部署形态、飞书通道。详见 §4.4。

## 1. Sig 产品全景

### 1.1 一句话定位

README 第一句：*"Always-on personal agent steward: remembers your work and dispatches it to coding agents on your machines."*——名字取 Sigma（Σ）：把各台机器上的 agent 汇聚到一个个人 agent。

关键定位句（spec §2）：**核心洞察是"在电脑前用户可以自己操作 agent；离开电脑时，用户想对管家说一句话，事情被办妥，办完了收到汇报"**。目标用户是"已经在用 Claude Code/Codex/pi 的开发者，**主要在手机上用 Sig**"。

### 1.2 架构一图流（对照 DoraHub）

```
你 → 浏览器 workspace（密码/passkey 登录）
       │ 一条连续对话（owner API 是同一对话的另一个视图）
       ▼
   Sig 管家（Cloudflare DO，pi-durable 运行时 + SQLite）
       │ WebSocket（connector 出站连接，配对码认证）
       ▼
   connector（每台机器一个守护进程，launchd/systemd）
       │ pi --mode rpc（每 worker 一进程）或 claude -p
       ▼
   你的仓库（写任务自动建 git worktree 隔离）
```

与 DoraHub 的架构差异：

| 维度 | Sig | DoraHub |
|---|---|---|
| 云端 | Cloudflare DO（免费额度内近零成本，全球边缘） | 阿里云 VM + systemd（Tailscale 私网） |
| 机器接入 | 机器上装 npm 包 connector，出站 WS，配对码 | hub 出站 SSH 部署 pi-env daemon，机器零安装 |
| 部署 | 一键 Deploy to Cloudflare / 给 coding agent 跑 runbook | git archive 打包 SFTP + hub.py 脚本 |
| agent 位置 | 管家自己是 LLM（用户配 key），worker 是机器上的 pi/Claude Code | 会话直接是 pi-durable agent（BYOK 多渠道） |
| 会话记录 | 留在机器上，按需流式读，**云端不存副本** | 全文进 hub SQLite（durable 会话） |

### 1.3 用户旅程（第一分钟 → 日常循环 → 异常路径）

**第一分钟**（它把这条线做成了明确的漏斗，每步有"下一步"指引）：

1. 点 Deploy 按钮 → Cloudflare 克隆构建部署（或把 runbook prompt 丢给自己的 coding agent 代办，README 里直接给了可复制的 prompt 文本）
2. 打开 Worker URL → 密码/passkey 登录（密码 ≥15 字符，弱密码启动时拒绝）
3. **setup 向导**：配模型 API key（不经过聊天/日志）→ 可选注册 passkey → 提示连机器
4. **没连机器也能聊**：空态文案"打个招呼，或让 Sig 开始一件事"——第一条消息就有回复（正反馈在 60 秒内）
5. **setup banner 常驻**：没配 key 时顶栏横幅"Sig 需要先配置模型密钥才能回复 + [添加密钥]按钮"；配了 key 没连机器时换成"需要 Sig 帮你写代码时，再连接一台机器即可 + [添加机器]"——**一次只提示一件事，做完自动换下一件**
6. 连机器：Machines 页生成一次性配对命令（10 分钟过期），机器上 `npx sig connect <url> <code>`，自动装系统服务
7. 注册仓库：Machines → Add directory → **目录浏览器**（浏览远端机器文件系统选路径，支持面包屑/上级/手输切换）或手输 `~/projects/my-repo`
8. 开工："检查一下 my-app 的登录流程" → 管家选机器选 agent 派活 → worker 跑起来

**日常循环**（手机为主）：

- 顶栏三个全局状态一目了然：**Machines 2/3 在线 · Running 1 · Needs you 2**（Needs you 有数字时浏览器标签页标题也带 `(2)`）
- 左栏 Threads 按**状态分组**：待处理（amber）/ 运行中（green 脉冲）/ 空闲（gray），每组带计数；每条带 unread 点、预览、agent·机器、相对时间
- 中间一条对话：默认"全部消息"；选某个 Thread 后 scope banner 提示 + composer 的 scope chip 变为"发送到当前事项"（**草稿按范围保留，切换不串**）
- 发消息 → 排队提示（"新消息会排队处理"）→ 管家回复流式上屏（正在写的字实时可见）
- worker 汇报：**三段式卡片**——结论（≤80字一句话）/ 做了什么（≤4 条 bullet）/ 需要你做什么（≤120字）+ tone 徽章（✅⚠️❌，由消息性质决定与 needsYou 无关）+ [查看详情] 链接
- **PR consent gate**：写任务完成且 git ahead>0 未推送 → 卡片多两个按钮 [同意]/[先不要]，点了才推送开 PR（按钮解析走服务端 outbound 行，不塞数据进按钮）
- 多个 quiet 通知 60 秒窗口自动合并成一条；waiting_you 永远立即推送

**异常路径**（它把异常当一等公民设计，这是质量差距的真正来源）：

- **机器离线 ≠ 任务失败**：调度时机器离线 → 立即告诉用户并给选择（等上线自动跑 / 换机器），**绝不默默替用户决定**；跑一半断连 → worker 标"失联"不标"失败"，等重连 reconcile（还在跑的继续、跑完的补收、被打断的自动尝试 resume，失败才问用户）
- **卡死检测**：worker 静默 8 分钟 **且** 进程树 CPU 累计几乎为零才判 stall（"安静但 CPU 热 = 在编译，不是卡死"）；第一击原地复活（同 worktree 续跑），第二击才算 error:stall
- **90 秒兜底窗口**：worker 问了问题 → 先给管家 90 秒尝试自己答（事实性问题）→ 窗口过期（LLM 挂了/预算超了）**核心代码直接把问题原文转发给用户**——用户的决策永远不会因为 LLM 不可用而丢失
- **预算降级**：今日花费超 DAILY_BUDGET → 事件不再唤醒管家，但 done 汇报/兜底推送/用户消息继续处理（顶栏花费变红提示）
- **会话记录查看器的 10+ 种状态**：每一种（机器离线/文件还没写/文件被删/读取中断连/connector 版本太老/…）都有专门文案和动作（重试/升级提示），**绝不让异常态显示成"空的成功"**

### 1.4 信息架构

单页 workspace（无前端构建，纯 HTML/CJS/ES modules，CSP 禁 inline script）：

```
顶栏：品牌 | Machines N/N · Running N · Needs you N | 今日花费 $x.xx | EN/中文 | 账户
左栏：All messages (⌘K) | 搜索 | Threads 按状态分组列表 | Machines 列表(在线/槽位) | 连接状态
中区：对话流（全部消息 or 聚焦 Thread，scope banner 区分）
      view tabs：[对话] [Agent sessions N]（同一 Thread 的两种看法）
      composer：scope chip + 回复 chip + 输入框 + 模型选择器 + 思考档位 + 发送
右栏：Workspace 视图 = Needs you 汇总 + Running + 最近动态
      Thread 视图 = 标题/状态/摘要/目标/repos + workers（分支/git facts/上下文%/PR 状态）+ 时间线
会话记录视图（独立页）：worker 的完整原始记录，流式按需读（cursor 分页，≤24K 分片，跟写中的文件 3 秒追读）
手机（≤650px）：底部三 tab —— Chat / Threads(带角标) / Machines —— 功能等价，不是阉割版
```

关键 IA 决策（ADR-0004/0005/0011）：
- **web 和 owner API 是同一条对话的两个视图**，不是两个频道——workspace 发的消息和 API 发的消息落同一 outbound 行
- **"Needs you"是对话里卡片的视图，不是收件箱**——卡片带着按钮出现在对话流里，右栏/顶栏只是聚合入口
- **选择 Thread 聚焦对话，不开启新对话**
- **会话记录是 Thread 的第二个 tab**，不是独立页面；打开它之后可以直接对这个 worker send/interrupt（ADR-0011：UI 已经消歧了目标，不必绕管家再推理一遍——手机上微操的延迟敏感场景）
- 双语：EN 默认 + 中文切换，用户/agent 内容不翻译

### 1.5 功能清单与优先级（它自己标的）

**P0（离了骂娘）**：密码/passkey 登录、setup 向导、一条连续对话、派活（机器/agent/分支路由）、三段式汇报、Needs you 决策卡、会话记录查看、机器配对/撤销、离线恢复 reconcile、resume 续跑、worktree 隔离、确认卡的确定性兜底（90 秒窗口）。

**P1（重要但可后补）**：PR consent gate、目录浏览器、今日花费/预算、卡死检测、卡内直接回复（reply chip）、草稿按 scope 保留、流式回复上屏（"正在写的字"）、消息发送失败重试、⌘K 搜索。

**P2（锦上添花）**：routine（定时任务）/watch（巡逻）/follow-up（自我闹钟）、记忆页面、双语文、安静合并推送、preview-machine（演示用假机器）、worker 微操直连（ADR-0011）。

值得注意它**砍掉了什么**：飞书通道（最初的 MVP 主入口，ADR-0003 整个废弃——"web 才是日常入口"）、多用户、原生 app/PWA、管家自己的执行环境（浏览器/沙箱）。**砍比加更见产品判断**。

### 1.6 恢复/导入场景设计（对我们四连 bug 的直接启示）

Sig **没有"导入"功能**——会话记录留在机器上按需读，云端只存摘要/时间线/决策。它的"迁移"是 **handoff brief**：换机器/换 agent/上下文爆了（≥80%）时，确定性地组装一份交接简报（目标/当前状态/关键决策/遗留/指针（分支、commit、改动文件）——**只带指针不带内容**，让新 agent 自己读代码），前一个 worker 的分支作为新 worker 的 base。

它的"恢复"是系统性的三层：

1. **协议层**：connector 重启后 `hello.workers` 全量对账（还在跑的继续、跑完的补收）；命令去重（cmdId）；事件去重（workerId, seq）水位
2. **进程层**：pi 进程死了从 session 文件 resume（固定续跑提示词，30s 退避，≤2 次/小时）；孤儿进程清理（子孙进程快照）；文件锁（一 worker 一进程不变量）
3. **语义层**：lost ≠ failed ≠ broken 三分；unreported（跑完没交报告）交给管家兜底分类；每种崩溃场景一张幂等键表（spec §11：7 种场景 7 个 key）

**对我们的启示**：我们的"pi 会话导入"本质是在做 Sig 明确不做的事（把外部会话全文搬进云端），而且没有场景级验收。短期不是砍功能，而是：①给导入链路建场景测试（从真实 pi 会话文件抽样，覆盖 envId/渠道名/thinkingLevel/双写四类坑的回归）；②导入后加"冒烟验证"步骤（导入完成 ≠ 成功，能发一条消息得到回复才算）。

## 2. 五个产品问题的回答（handoff §0 预埋）

### Q1 它的用户第一分钟体验是什么？

**打开 → 密码 → setup 向导（模型 key）→ 没连机器也能聊（60 秒内得到第一次正反馈）→ banner 提示连机器 → 配对命令复制粘贴 → 注册仓库（目录浏览器）→ 派第一个活。**

每一步有且只有一个"下一步"，setup banner 做成状态机（缺 key 提示 key，缺机器提示机器，都不缺就消失）。空态文案直接给出行动指引（"打个招呼，或让 Sig 开始一件事"）。**这条线有专门的文档定义**（README Get started + agent-deploy/agent-connect runbook + ADR-0007 agent 代部署）。

对照 DoraHub：我们打开就是会话列表+新建按钮，空态引导停留在"最近会话 6 条"（WelcomePane），没有定义过"第一分钟"。**差距不在功能在旅程定义。**

### Q2 它的"会话"概念对用户意味着什么？

用户眼里：**"我有一个替我干活的助理，我和它有一段连续的对话"**。事项（Thread）是背后的组织层——用户在全部消息流和"聚焦某件事"之间切换，永远不面对"一堆聊天窗口"。每个事项是一个可持续追加的目标（"昨天那个登录 bug，今天补单测"直接续上），不是一次性对话。

对照 DoraHub：用户眼里是"一堆会话，每个会话 = 某台机器上的某个 agent 现场"。**这两个心智都成立，服务不同场景**（亲自干 vs 派活）。我们的 fork/跨机迁移其实已经有"事项"的影子（一件事换机器继续），但没升格成概念。

### Q3 它怎么做"多设备/跨机"（我们最核心卖点）？

- **接入设备侧**：云端 DO 是唯一状态源，任何浏览器密码登录看到同一条对话——和我们的"会话是家，设备是窗口"完全同构
- **执行机器侧**：connector 出站 WS + 一次性配对码 + 每机独立凭证可撤销 + 目录注册（repo 白名单）+ 槽位（并发上限）声明
- **跨机接力**：handoff brief（指针不内容）+ 前 worker 分支作 base + relay 风格（同一 agent 同一机器优先 resume，不满足才新开会话）；机器选择确定性规则（用户点名 > 上次机器 > 在线 > 空槽多）
- **离线语义**：temporarily away ≠ failed，重连 reconcile 三分支

对照 DoraHub：我们执行机接入是 SSH 出站（机器零安装，比 connector 轻）、跨机是**工作区文件级迁移**（比 handoff brief 重，搬真实文件）。我们的迁移是差异化能力，保留。**它比我们强的点是"机器选择"和"离线语义"的产品化表达**（用户可理解的语言），以及**手机完全等价**。

### Q4 哪些是 P0（离了骂娘），哪些是 P2（锦上添花）？

见 §1.5。最能刺激我们的是它的 P0 清单里有三个我们完全没有的东西：**Needs you 聚合、确定性兜底（LLM 挂了用户决策也不丢）、离线恢复的产品化语义**。而我们的 P0（实时流式/steer/确认卡/双设备同步）在它那里是 P1 甚至没有（它没有"驾驶"概念）——**说明我们的核心资产它抄不走，它的体验基线我们缺**。

### Q5 它的导入/恢复场景怎么设计？

见 §1.6。一句话：**它用"不做导入 + 三层恢复 + 幂等键表"绕开了我们正在踩的整个雷区，而它做的每个恢复场景都有对应测试文件**（crash-recovery.test.ts / e2e-restart.test.ts / reconcile.test.ts / stall-reap.test.ts / offline-dispatch.test.ts）。

## 3. 差距分析（对照 §2 功能清单）

### 3.1 我们有、但没对齐用户心智的

| 功能 | 现状 | Sig 的对齐方式 |
|---|---|---|
| 会话列表 | 按项目分组 + 时间窗；卡片有运行徽章 | 按三态分组（待处理/运行中/空闲）+ unread——**"回来第一眼"是"什么在等我"** |
| 确认卡 | 会话内 ConfirmationCard，逐会话看 | 顶栏 Needs you N 聚合 + 右栏汇总 + 标签页标题带计数——用户不用翻 |
| 会话完成 | 流式戛然而止（agent settled 无感知） | 三段式汇报卡 + tone 徽章（✅⚠️❌） |
| 排队消息 | InboxBar 显示"⤴ 转向排队中 · id" | composer 状态行用自然语言（"新消息会排队处理"），排队数>1 显示"还有 N 条" |
| 手机 | 驾驶舱无管理功能（设计如此） | 三 tab 等价功能，Threads 带角标 |
| 执行机状态 | /api/executors 缓存探测，侧栏徽章 | 顶栏 Machines N/N 全局可见 + 每机槽位 used/max + 离线会话标"失联"不报错 |
| 空态 | WelcomePane 最近 6 条会话 | 行动指引文案 + setup banner 状态机 |

### 3.2 我们缺的（按用户痛感排序）

1. **unread**：手机上"哪个会话有新动静"全靠打开看——Sig 用 unread 点 + 手机 tab 角标 + 标签页标题计数三层表达
2. **收尾汇报**：跑完的会话没有"结果"层——只有原始流式记录，没有"结论 + 做了什么 + 要不要你做事"
3. **Needs you 聚合**：确认卡埋在会话里，多会话并行时手机上要挨个翻
4. **失联语义**：执行机断线时用户看到的现状接近"报错"，Sig 区分"机器暂时不在"（amber 提示）和"任务失败"（red）
5. **卡死检测**：会话静默多久都没人管（我们有 agent status，但没有"X 分钟没动静"的提示）
6. **花费可见**：模型花了多少钱无处可看
7. **新建会话选 cwd**：手输路径（要记住每台机器的路径格式）；Sig 有目录浏览器（面包屑/上级/手输切换，还处理了 Windows 分隔符和 ~ 展开——虽然它 connector 不支持 Windows，UI 倒是留了）
8. **发送失败重试**：网络抖动时消息丢了就是丢了（Sig 的 user message 有 pending: sending/failed 态 + 重试按钮）
9. **功能需求层文档**：自省 #5，Sig 的 spec.md 是 375 行的 PRD（用户/场景/原则/概念表/状态机/验收边界/MVP 范围/开放问题），我们的对应物缺位

### 3.3 我们不缺且有特色的（对齐时保住）

- **现场感**：流式 markdown 增量渲染、edit diff、工具卡状态戳（讫/误/阻）、框缘闭合签名动作——Sig 的会话记录查看器是"读档案"，我们是"看直播"
- **steer/确认卡的实时性**：S1-S4 是我们验证过的核心资产
- **pi 会话管理中心**：扫描/元数据/导入/删除/跨机搬运——Sig 明确不做（会话留机器上）；这是我们"迁移已有工作"的差异化
- **工作区文件级跨机迁移**：比 handoff brief 重但完整（搬真实文件 + 校准提示）
- **BYOK 多渠道十模型**：Sig 单 key 单模型（+composer 里切换）
- **自托管 hub**：一台 VM + Tailscale，无 Cloudflare 依赖（对国内网络是真实优势——Sig 的 workers.dev 在大陆被墙，它文档里专门写了要绑自定义域名）
- **执行机零安装**：SSH 出站部署 daemon vs 要在每台机器 npm install

## 4. 移植方案（分级，待拍板）

> 每项标注：价值 / 成本 / 是否触碰硬约束。**P0 全部不碰 IA 骨架**（侧栏两栏/手机单栏/设置三页签/⋯菜单结构不变，改的是列表内容组织、徽章、卡片、文案）。

### 4.1 P0 —— 体验基线（建议本迭代做，2-3 个会话）

**P0-1 会话三态分组 + unread 点**（价值★★★ / 成本中）
- 侧栏列表分组从"按项目"改为"等你（amber，有未处理确认卡或 agent 停在问题上）/ 运行中（green，status=running）/ 空闲（gray）"，组内保持项目信息（cwd→项目名徽章保留在卡片上）
- ConvCard 加 unread 点：会话有未读的 assistant/tool 事件时亮，点开会话清除
- 状态全部服务端派生（conv status + 确认队列推导），不在前端算——遵守"服务端是真相"（坑 #30）
- 手机列表页同样分组 + 顶栏"运行中 N · 等你 N"行

**P0-2 Needs you 聚合入口**（价值★★★ / 成本中）
- 桌面：SidebarHeader 加"等你处理 N"徽章（amber），点击弹出聚合列表（所有会话的未处理确认卡摘要 + 跳转）
- 手机：列表页 header 同样入口（这是驾驶舱加的第一个"管理"功能，但它是只读聚合 + 跳转，符合驾驶舱克制原则）
- 底层：/api/conversations 列表项加 `pendingConfirmations` 计数字段（服务端从确认队列聚合）

**P0-3 收尾汇报卡**（价值★★★ / 成本中）
- agent settled 时在会话流末尾插一张"收尾卡"：tone 徽章（✅ 完成 / ⚠️ 需要注意（有 error 级工具结果或 stopReason=error）/ ⛔ 失败）+ 一行结论（自动命名器已能生成，复用其摘要能力）+ 做了什么（工具调用统计：改了 N 个文件 / 跑了 M 条命令）+ 需要你（有未处理确认卡时）
- 纯确定性生成（数事件，不调 LLM），与 Sig 的"核心模板不依赖 LLM"同哲学
- 手机上这就是"这个会话跑完了没有/成没成"的答案

**P0-4 手机等价化（第一刀）**（价值★★★ / 成本低）
- 手机列表页加 pi 会话区入口（时间窗列表照搬侧栏逻辑）——手机上现在完全看不到 pi 会话
- 手机 header ⋯ 菜单已收敛，保持；但"等你 N"入口在列表页可见（P0-2 的一部分）
- 不做设置三页签手机版（真低频），只在 ⋯ 菜单加"关于/渠道"最小项——**手机从"无管理"升级为"只读+跳转"**

**P0-5 导入链路场景测试 + 冒烟验证**（价值★★★ / 成本中，直接回应自省 #3）
- 建 `scripts/pi-import-cases/`：从三台机器的真实 pi 会话抽样（覆盖：自定义渠道模型/thinkingLevel 各档/带 attachments/超长会话/跨机路径编码），跑导入→对比 entries 快照
- 四连 bug 各写一个回归 case（envId 丢失/渠道名不存在/thinkingLevel 不在模型支持列表/双扇出）
- 导入完成后加**冒烟验证**：向导入的会话发一条 probe 消息（或至少 dry-run 渠道解析），失败则在导入结果里显式警告"导入成功但该会话使用的模型 X 当前不可用，请切换模型"——把"导入成功"的定义从"文件搬完"升级为"能继续对话"

**P0-6 空态/错误态基线**（价值★★ / 成本低）
- WelcomePane 空态（无任何会话）改为行动指引："第一步：新建会话，选一台执行机" + "或从侧栏导入你已有的 pi 会话"
- 渠道 key 全失效/执行机全离线时的 banner（对照 setup banner 状态机：一次只提示一件最要命的事）
- 执行机离线：会话/列表显示"机器离线"amber 态（现在探测失败的灰化已有，补会话内提示），新建弹窗里离线执行机禁选 + 原因提示（已有部分，验收补齐）

### 4.2 P1 —— 结构性提升（下下个迭代，3-4 个会话）

**P1-1 失联语义**：执行机断线时，其上运行中的会话标"失联"（amber，不红），断线期间 steer 消息排队（重连后投递），重连后对账（会话还在跑→继续；已结束→拉快照）。需要 server 侧 per-env 会话状态机，工作量不小但直接补强"崩溃是暂停不是损失"的产品承诺
**P1-2 卡死检测**：运行中会话 lastEventAt + N 分钟（建议 15-20）无事件 → 会话卡/列表标"⏸ N 分钟没动静"。纯服务端（ws 扇出时记 lastEventAt），成本低
**P1-3 今日花费**：顶栏/设置"关于"页显示当日 token 花费（pi usage 汇总，服务端聚合 per-day）。开源前的信任基建
**P1-4 目录浏览器**：新建会话选 cwd 时浏览执行机文件系统（daemon 文件 API 已有 listdir 能力，坑 #4 的通道）。手机上收益最大（手输 Windows 路径不可能）
**P1-5 发送失败重试**：Composer 消息 pending/failed 态 + 重试按钮（WS 断时 HTTP 兜底发送）
**P1-6 功能需求层文档**：写 docs/spec.md（对齐 Sig 的 PRD 结构：用户/场景/原则/概念表/验收边界），把 §3 的差距分析固化成"每个功能为谁/解决什么/验收标准"。**这项是自省 #5 的答卷，做完后 roadmap 和 handoff 都有依据**
**P1-7 会话摘要面板**：桌面右栏（现在是两栏，可在会话页 header 加"摘要"展开区，不新增栏位——IA 不动）：自动描述/关键词（已有 conv_meta）+ 工具统计 + 时间线（事件流摘要，L2 层）。手机折叠进 ⋯ 菜单"会话详情"

### 4.3 P2 —— 远期/加分（进 roadmap.md）

- **routine（定时任务）**："每天 9 点总结昨晚三台机器的会话动静"——对我们是驾驶舱+值班员的自然延伸，但要先有收尾汇报卡（P0-3）做原料
- **双语**：开源前的国际化（我们中文为主，暂缓）
- **quiet 合并推送**：PWA 推送落地后再谈
- **会话记录跟读**（live tail）：正在跑的会话在"另一个浏览器窗口"跟随——我们已有实时流，这是把流扇出给"观察者"角色，架构上顺
- **PR/推送 consent**：写类任务完成后"要不要推送"的确认——我们 guard 是事前拦截，这个是事后决策，可结合确认卡做
- **handoff brief**：fork/迁移时自动生成"指针式交接简报"（现在迁移有校准提示，可加摘要）——挂在跨机迁移这个差异化功能上升级

### 4.4 明确不移植清单（及理由）

| 项 | 理由 |
|---|---|
| 管家 LLM 调度层（find_threads 路由/autonomy 分级/provenance 门禁） | 我们是"亲自驾驶"心智，用户直接选执行机选模型，不需要中间再隔一个 LLM 决策层——多一层就多一层不确定性 |
| 记忆模块（2400 字常驻层/容量驱逐/两阶段写入/遗忘可见） | 我们的持久化单元是 pi-durable 会话本身（完整上下文常驻），管家式"压缩记忆"解决的痛点在我们这里不存在 |
| Cloudflare DO 部署/一键按钮 | 自托管 hub + Tailscale 是差异化（大陆网络现实 + 数据完全自主），不换 |
| connector 常驻守护进程 | SSH 出站零安装更轻，两架构各有代价（我们要管 SSH 密钥，它要用户装 npm 包），不换 |
| 飞书通道 | 它自己都废弃了（ADR-0003） |
| Thread（事项）层重构 | 大改且与"会话=现场"心智冲突。我们用"跨机迁移+fork+收尾卡"覆盖同一需求的 80%。**长期可议，短期不做** |
| 无前端构建的纯 CJS UI | 工程口味问题，React+Vite 无罪 |

### 4.5 工程质量侧的学习（不占迭代，随手做）

- **CONTEXT.md 词汇表**：统一产品词汇（我们现在"会话/对话/conv"、"确认卡/ConfirmationCard/guard"混用，handoff 和代码注释各说各话）——一个 60 行的文档
- **"Implemented (issue #N)" 回写文档**：Sig 的 design 文档里每个落地决策都有回写标记，文档与代码不漂移；我们 handoff 已有这个精神，把它延伸到 design/ 的 ADR
- **场景测试规模**：Sig 100+ 测试文件里一半是产品语义测试（intervention/stall-reap/offline-dispatch/report-merge）；我们 15 项 ws-test + P0-5 的导入 case 是起点
- **commit 粒度**：它一个 issue 一个 PR，PR 描述里带 design 文档锚点——开源协作的姿态值得我们提前养成
